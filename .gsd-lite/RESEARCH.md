## 2. 採用技術の公式情報（official_docs）

- **WebMCP 草案**（W3C Web Machine Learning CG、Draft Community Group Report **2026-10-09** 版、https://webmachinelearning.github.io/webmcp/）: `document.modelContext.registerTool(tool, { signal, exposedTo })` → `Promise<undefined>`。`ModelContextTool` は `name`（1〜128 文字、ASCII 英数と `_ - .`）/ `title`（任意）/ `description`（必須）/ `inputSchema` / `execute(input, { signal })` / `annotations`（`readOnlyHint` / `untrustedContentHint` / `consequentialHint` / `debugging`。既定 false）。`getTools()` はソート済み一覧、`executeTool()` は**文字列化した結果**を返す。`toolchange` / `toolactivated` / `toolcancel` イベント。description の長さ・ツール数の上限は規定なし。**部品・入れ子・リソースの概念は無い**
- **Chrome Imperative API**（https://developer.chrome.com/docs/ai/webmcp/imperative-api、2026-09-21 更新）: 上と同じ 4 annotations（`debugging` は Chrome 156 から）、`exposedTo`、`getTools()` はアルファベット順、`executeTool` に JSON 文字列を渡す形は Chrome 155 で非推奨（オブジェクトを渡す）。結果の形式・サイズの規定なし
- 影響: 5 ツールの登録形・annotations は現行コード（`ui-tools.js:97-99`）のままで草案に合う。`components[]` は `ui_get_screen` の結果 JSON の一部で、WebMCP 側に対応物が無い = 契約文書（`docs/webmcp.md`）で定義するだけでよい。子パッケージの `webmcp.description` は外部パッケージ由来の文字列なので、既に立っている `untrustedContentHint: true` の範囲に入る（`docs/webmcp.md:17`）。`title` フィールドは草案の**ツール**の表示名で、`components[].title` とは別物（混同しないよう文書で「パッケージの `title`」と書く）
- `docs/webmcp.md:5` の「2026-10-02 に確認した草案」は日付と `executeTool` の戻り（文字列）を更新する余地があるが、要件外。受け入れ 7 の `docs/webmcp.md` 更新のついでに日付だけ合わせるかは plan 判断
- serde_json: `BTreeMap` 由来のキー順はアルファベット順（`docs/components.md:114` に「キー順に依存した読み方をしてはならない」）。`Vec<Component>` の**配列順**は契約（instance の辞書順）として明記する。`BTreeMap<String>` の順序は UTF-8 バイト順 = コードポイント順で、JS の `<` 比較（UTF-16 code unit 順）と BMP 外の文字で食い違いうるが、itemId は ASCII 英数が実用上すべてなので文書には「バイト順（ASCII なら辞書順）」と書く

## 3. 同種の設計（similar_oss）

- **アクセシビリティツリー / Playwright の aria snapshot**: エージェント向けの UI 表現は「role・name・state（`hidden` / `disabled` / `expanded`）・参照 ID」を持つ木のスナップショットで、操作は参照 ID で行う（Playwright MCP、agent-desktop。https://tianpan.co/blog/2026/07/02/the-accessibility-tree-is-your-newest-public-api 、https://www.mintlify.com/lahfir/agent-desktop/guides/snapshot-options）。本件の `widgets[].key`（接頭辞付き）+ `components[].instance` + `hidden` はこの形の縮約で、**非表示要素を「出すがフラグを付ける」**のはブラウザの a11y ツリーの `hidden` 状態と同じ選択（Playwright の snapshot は非表示を省くが、本件は D6 で「あるが操作できない部品」を知らせる方針）
- **MCP の tool annotations**（`readOnlyHint` 等）は「ヒントであって強制ではない」（Chrome / CopilotKit の注意）。`components[]` も「説明情報であり許可 action を変えない」（R2）と同じ位置づけで、文書にその一文を残す
- 作らなくてよいもの: 無し。ドロップインで使えるライブラリは無く（WebMCP のラッパー npm（`@mcp-b/*`、`useWebMCP`）は登録の糖衣で、部品一覧の概念を持たない）、`components[]` は本リポジトリの `Scene` 拡張として書く
- 盗める設計: a11y ツリーの「親の非表示は子孫に伝播」（`aria-hidden` の継承）= R2 の「祖先が非表示なら子孫も非表示」。Playwright の「スナップショットは操作のたびに取り直す」= `docs/webmcp.md` の既存手順 4（revision を使って再参照）
