# DOM / Canvas フォントサイズ統一

## 目的

同じ画面・同じ部品の文字が DOM 版と Canvas 版で違う大きさに見える問題を解消する。
マイルストーン: `renderer-font-size-parity`。

## 要求

- 現在の DOM 版の部品別フォントサイズを基準に Canvas 版を合わせる。全ての文字を一律のサイズにはしない。
- 両レンダラーで対応する全共通部品の文字を対象とする。基本ラベル、フォームのラベル・値・選択肢、ボタン、パネル・ウィンドウ、表、タブ、ツリー、メニュー、通知、ダイアログ、追加部品、図表・文書の文字を調査し、対応関係と差を一覧化する。
- Canvas 上の通常描画と編集中の DOM オーバーレイで文字サイズが変わらないようにする。
- 比較デモと独立ランタイムの両方で一致させる。ホスト CSS の継承やフォントの読み込み、拡大率・DPR が原因となる場合は実際の原因を直す。
- 字体・太さ・行間・文字計測・余白はサイズ一致と欠け防止に必要な範囲で調整する。
- 部品のサイズ定義を再利用できる既存の仕組みを優先し、新しい依存関係は追加しない。具体的な実装方法は research / plan で決める。

## 受け入れ基準

1. 全共通部品について、文字の役割ごとの DOM の実効 CSS px と Canvas の描画時の CSS px が一致することを確認する。該当しない部品と既存の描画差は理由付きで一覧に残す。
2. 実ブラウザでフォント読み込み後に同じ画面・文字を比較する。数値確認に加え代表画面の画像を目視し、文字サイズ差が解消していることを確認する。アンチエイリアスの画素単位の完全一致は求めない。
3. Hello World、フォーム、Grid、パネル・ウィンドウ、ギャラリーを代表画面とし、DOM / Canvas の通常表示、フォーカス、編集開始・確定・取消を確認する。共通状態・入力・操作を保持する。
4. 日本語・英数字・空文字・長文を扱い、既存の折り返し・省略・クリップ仕様に対して新たな文字の欠け・重なりを増やさない。
5. デスクトップ幅と約390px幅、100%と200%相当の拡大、DPR 1 / 2 で実効サイズと描画・入力位置を確認する。DPR エミュレーションと実際のブラウザ拡大を区別して記録する。
6. ライト / ダーク切替と再描画でサイズ一致が保たれ、編集中の入力・フォーカスが失われない。実IMEを確認できない場合は限界として記録し、合成イベントを実IME確認と扱わない。
7. 変更に適した回帰確認、build、check を通す。定数の写しだけのテストは増やさず、実際の CSS と描画・操作を確認する。

## スコープ外

- 全体デザインの刷新、ユーザー向け文字サイズ設定、DSL / テーマへの新しいフォント設定 API。
- サイズ一致に関係のない全余白・行間・字体・太さの完全統一。
- 比較デモ外側のページ UI、外部 iframe 内や画像に焼き込まれた文字。
- 新しい部品や非対応機能の追加、公開・デプロイ、ループやスキルの改修。

## 用語

- DOM 版: DomRenderer とランタイム CSS で描画する UI。
- Canvas 版: CanvasRenderer の Canvas 2D 描画と入力用 DOM オーバーレイ。
- 共通部品: 同じ Scene の同じ Widget を両方式で表現できる部品。
- サイズ一致: 同じ文字の役割に同じ実効 CSS px のフォントサイズを適用すること。
