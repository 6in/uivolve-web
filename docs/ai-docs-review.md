# AIによる開発のための文書・スキル点検

2026-10-04。状態: 点検と修正の記録。APIの根拠は[AI参照入口](ai-development.md)から選ぶ現行契約とする。

## 対象と判断基準

README、docsの35文書、開発スキル2つと12リファレンスを対象に、参照経路、実装状態、APIの名称・型・階層、実行例、配布後の自己完結性を点検した。HTTP、ホスト登録、共通関数など更新に関係する契約は実装・テストと照合した。すべての部品の全属性を改めて動作検証したという意味ではない。

AIが短い文脈でも必要な契約を特定できること、未実装APIを生成しないこと、例から設定の不足なく実装できることを優先した。文章の読みやすさだけで判断せず、次の不整合を修正した。

| 発見                                                         | AIの実装への影響                                          | 対応                                                                           |
| ------------------------------------------------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------ |
| README、画面契約、GET/RPC文書、I/O referenceのPOST未対応記述 | 対応済み機能を利用不可と判断する                          | http_getの範囲とhost_callの範囲を区別し、[現行HTTP契約](http-adapter.md)へ接続 |
| 画面トップレベル属性表にoperationsがない                     | 未知属性と判断、独自URL組み立てを生成                     | 画面契約へ宣言とoptions階層を追加                                              |
| アダプター設計が一律未実装、例は将来APIを混在                | host_callを避ける、または存在しないWebSocket/DB APIを呼ぶ | 冒頭に実装状態表、将来例のラベル、現行契約への優先リンク                       |
| host_callの起動設定、args、完了型が1箇所で揃っていない       | アダプター未登録、methodの誤配置、data/error型の取り違え  | 起動JS・画面YAML全体・Rhai・制約・エラーをHTTP契約へ集約                       |
| host_resultがアーキテクチャのABI一覧にない                   | ABIやeffectsの追加経路を見落とす                          | ABI一覧とHostEffectsの責務・動的引数検証時点を追記                             |
| スキル末尾に新しい計算関数の案内が埋もれる                   | 未登録関数を生成、FLOATやコード単位で代用                 | 機能別referenceを追加し、入口表で日付・金額・Unicodeへ振り分け                 |
| デモの選択欄をindex.htmlで手動追加する指示                   | カタログと表示の重複管理                                  | screen-catalog.jsからの生成に修正                                              |
| 部品移植文書がBorderを未対応と記す                           | 利用可能な配置を避ける                                    | 共通レイアウト契約の対応範囲へ接続                                             |
| 計画・履歴が契約と同じ入口に並ぶ                             | 古い制限や将来案を現行仕様と誤認                          | AI入口と計画の状態表示を追加し、必要な契約だけ選ぶ構造に整理                   |

## 検証

- HTTP契約のYAML/Rhaiを直接抽出し、実WASM＋HostEffects＋ResourceClient＋httpAdapterで実行した。複数パス変数、日本語・予約文字、PATCHのJSON本文、成功・不正引数時のloading解除を確認する[テスト](../tests/documented-http.test.js)を追加。
- docs:checkでローカルリンク、skills:bundleで両スキルの独立した配布物を再生成。skills/distributionテストでリポジトリ外へ移動した後のリンク、メタデータ、最小YAML/Rhaiを検査する。
- 構造と実行例の検証であり、別AIの初見生成成功率を数値測定する試験は実施していない。将来その評価を行う場合は、このHTTP例・日付例・金額例・Unicode例を共通課題にする。
