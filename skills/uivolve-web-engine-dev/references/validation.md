# ビルド・検証・互換性

[開発への参加](../../../CONTRIBUTING.md)、[検証基準](../../../docs/testing.md)、[起動・配信](../../../docs/operations.md)を対象チェックアウトで確認する。

- Rust変更時はWASMを再ビルドして確認する。新しい部品やAPIを古いpublic/engine.wasmで検証しない。
- エンジン・ホストのコード変更では、リポジトリのbun run test/build/check/docs:checkを実行する。意味のある状態・座標・イベント・失敗時の保持を検証し、実装の定数を写すだけのテストを増やさない。
- 文書・スキルだけの変更では内容とリンクを確認する。配布スクリプトやサンプルを追加した場合は実行し、配布先だけでリンクと例が使えることを確かめる。
- 表示・入力の変更は実ブラウザのDOM/Canvas両方で確認する。WebMCP、IME、HTTP/CORSは変更した契約に応じて確認する。合成compositionイベントをOSの実IME保証としない。
- DSL、Scene、ABI、登録済みRhai APIを変更したら以前の画面との互換性と配信時の更新手順を記す。再描画のCPU時間をGPU完了やFPSと混同しない。
- 実行例・契約文書・スキルの案内を揃える。配布用スキルは資料のスナップショットなので、更新後に再生成する。
